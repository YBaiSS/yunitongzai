# Literature Snowball · 文献检索拓展

## Overview

在论文写作初期，用一组起点文献为尚模糊的想法寻找既有研究的共鸣，或为研究方向定位。工作方式是滚雪球：从初级文献库的综述段落与参考文献出发，逐轮提出"有研究价值、可检索执行"的拓展方向，由用户选定后输出分级文献清单，用户手动检索并把新文献加入文件夹，再进入下一轮。建议的文献必须来自初级库文献实际引用过的内容，不凭模型自身记忆推荐。

## 核心铁律（任何一轮都不得违反）

1. **只推荐初级库文献引用过的内容**。清单中每条文献必须能在某篇初级文献的参考文献区或正文引用中找到出处。凭模型记忆补出的文献，即使极可能真实存在，也只能放入"线索（需验证）"栏并明确标注，绝不混入正文清单。宁可少而准，不可多而虚。
2. **必须把方向选择权交给用户**。先给方向判断（含依据与代价），等用户选定后，才输出该方向的详细文献清单。严禁一次性倾倒全部方向清单，严禁替用户拍板。
3. **方向判断要有依据**。每个方向必须能指回初级文献中的具体语句（哪篇、哪段、说了什么），不得写"学界普遍关注"这类无出处寒暄。
4. **每次运行都要读检索地图**。检索地图（见下）是跨轮次状态总账，防重复推荐、记线索演进。读文件夹前先看它，本轮结束必须更新它。

## 输入确认

开始前先确认两件事，缺一不可：

1. **文件夹路径**：确认用户给出的是存放初级文献 PDF 的文件夹绝对路径。若路径下没有 PDF，要求用户提供正确路径后再继续。
2. **研究问题表述**：请用户用一两句话说出当前想研究的问题（允许模糊）。若用户表示问题还很模糊、说不清，则从文献中归纳 2~3 个候选问题表述，向用户确认哪一个更接近本意后以该表述开工，并在检索地图中记录"最初表述"与"轮次N表述"以便追踪演进。

## 运行脚本（扫描 PDF）

用本技能自带的扫描脚本做第一遍粗筛，将文本抽取、参考文献定位、综述段落初筛交给脚本，节省上下文并保证不漏文献：

```bash
python <skill目录>/scripts/scan_library.py <知识库文件夹路径>
```

脚本依赖 pypdf、pymupdf 或 pdfplumber 三者之一，按此顺序自动探测。若环境中都没有，先安装其一再运行：`pip install pypdf`。

脚本默认在知识库文件夹下生成 `_检索扫描/` 目录，产出：每篇的参考文献原文与切分条目（`refs/`、`entries/`）、综述/评论候选段落（`hits/`，含页码与命中信号词）、跨篇共引候选（`co_citations.txt`，启发式匹配，需人工核对）、结构化索引（`index.json`）与扫描摘要（`SUMMARY.md`）。扫描完成后通读 `SUMMARY.md` 与各篇 `hits/*.md`。

若脚本提示缺解析库且无法安装，或某篇 PDF 是扫描件（无文本层，摘要中标"疑似扫描件"），改用 Read 工具直接多模态阅读该 PDF。脚本的文本抽取只是辅助定位，命中段落常被截断或丢失版式，判断方向前应回到原文核对语境。

## 工作流程

### 第 0 步：读检索地图，明确轮次状态

检查知识库文件夹内是否存在 `_检索地图.md`（文件名以 `_` 开头，扫描脚本会跳过它）：

- 不存在：按 `<skill目录>/assets/templates/检索地图模板.md` 的格式创建，填入研究问题与文件夹内现有 PDF 清单。
- 存在：通读全文，重点关注"已推荐文献总账"（本轮所有清单严禁与总账重复推荐同一条目）、"轮次记录"里上一轮的收尾与"下一轮注意"，以及"研究问题演进记录"中最新的问题表述。若总账为空但检索地图存在，属异常，先向用户核对。

### 第 1 步：粗扫

运行扫描脚本（见上），拿到 `_检索扫描/` 输出。逐篇浏览 SUMMARY，记下：每篇文献的主题、是否有综述段落、参考文献体例（编号制/作者-年制，影响后续条目引用方式）。

### 第 2 步：精读综述与评论内容

按优先级阅读，控制篇幅：

1. `_检索扫描/hits/*.md` 中的高分段落；对其中信息密度高但被截断的段落，回到 PDF 原页精读（用 Read 工具定位页码）。
2. 通读 `_检索扫描/entries/*.txt` 全部参考文献条目。
3. 需要时扫 `co_citations.txt`，跨篇共引往往是领域核心节点，也是低成本高回报的检索起点。
4. **双栏期刊的兜底**：双栏版式常使整页连排、综述段命中稀少甚至为零（hits 大面积为空时应警觉）。此时改用 Python（pypdf）批量抽取每篇前 3~5 页文本（引言与文献综述通常在此），逐篇精读；抽取乱码严重（字体子集化）的篇目，改用 Read 工具直接读 PDF 对应页。

阅读时带着三个问题：这些文献共享什么前提？在哪里出现分歧或缺口？作者各自承认受谁影响、反驳谁？把与这三个问题相关的证据（原文语句 + 出处页码/条目号）记录下来，供第 3 步引用。

### 第 3 步：形成拓展方向判断（全流程枢纽，最关键的步骤）

通读 `<skill目录>/references/direction_heuristics.md`，按其标准产出一组方向判断。产出 3~4 个方向（可含一个明显更弱的候选作为对照）。每个方向按如下格式组织：

- **方向名与类型**（脉络溯源 / 争论对垒 / 概念迁移 / 方法范式 / 经验对照 / 边界反例）
- **一句话命题**：沿这个方向走下去，研究问题会变成什么样子
- **判断依据**：哪篇初级文献的哪一段（或哪几条参考文献）支撑该方向，尽量引用原文
- **研究价值**：它指向什么分歧、空白或可修正的预设
- **代价与不确定性**：文献可得性、可能跑偏的风险、会否变成综述复述

方向宁可少而精，写不出依据的不要列。这一轮判断质量的高低，直接决定雪球滚得对不对。判断完成后，把方向清单作为一道多选题交给用户选择，附一句开放提示：用户也可以不受选项限制自己描述方向（用提问工具或直接在对话中列出选项均可）。给用户留足考虑时间，不得在用户选定前进入第 4 步。

### 第 4 步：输出选定方向的拓展检索建议

用户选定方向后，按"三分级清单"输出：

- **必读**：直接支撑该方向命题的核心文本
- **选读**：提供旁证、语境或可比较对象的文献
- **线索（需验证）**：仅见于转述、或信息不全、或确需模型知识补充的条目

每条文献标注：
1. 作者（年份）与标题（照录初级库参考文献原文；条目信息不全时如实说明）
2. 出处：源自哪篇初级文献的参考文献第几条 / 正文哪一页哪段
3. 被引语境一句话：该文献在初级文献里是作为理论基础、争论对手还是经验例证被引用
4. 建议检索关键词：忠实原概念的中英文关键词 + 指向该方向的限定词，并注明关键词取自哪段原文
5. 一句"为什么读它"，落到研究价值（给你一个新争论对手 / 一条可比经验 / 一处可修正的预设……）

清单开头给一行优先级说明：建议最先检索哪一条、为什么它最能撬动下一步判断。清单结尾提醒用户：本清单全部来自初级库文献的引用；检索到的新文献请放入文件夹，下一轮继续。

### 第 5 步：更新检索地图

按 `检索地图模板.md` 的结构，在本轮记录中追加：扫描情况、提出的方向与依据、用户选定方向及理由（用户未说明则省略）、清单摘要、下一轮注意；并把本轮清单条目去重写入"已推荐文献总账"，状态记为"待检索"。若用户此前有过追问或提出过新疑问，同步更新"研究问题演进记录"。

### 第 6 步：计算库内引用网络（仅在用户表示暂停或收束时执行）

判断"哪几篇是核心文献"不能凭轮次顺序或阅读印象。第一轮补入的文献未必占据枢纽位置，第二轮补入的文献反而可能是全库被引最多的一篇。这一步把地位判断换成可核对的数字。

**只在收束时算，不每轮都算**。理由是网络只在库内成网，早期节点少、边薄，入度会在 0 到 4 之间跳动，噪声大于信息；等到收束时全库已经成形，算出的结果才稳。若用户在滚动中途明确要求，照办并注明依据轮次。

运行：

```
python <skill目录>/scripts/network_analysis.py <知识库文件夹路径> [--skip-cocite "某篇文件名片段"]
```

脚本读取 `_检索扫描/index.json` 与 `_检索扫描/refs/`，输出 `_检索扫描/network.json` 与 `_检索扫描/network_report.md`，内含互引边表、入度/出度分层、库外共引锚点。

三点操作要点：

1. **中文期刊文件名通常不含年份**，自动推断多半失败。脚本会生成 `_检索扫描/libmap.template.json`，照它填写 `libmap.json`（片段 → 作者数组、年份、标签）后重跑。这一步无法省略。
2. **共引统计会受同刊他文混入影响**。若某篇的参考文献区包含同刊另一篇文章的条目，用 `--skip-cocite` 排除该篇，并在报告中说明。
3. **作者重名会造成误判**。抽查若干条边，确认作者名与年份确实指向同一篇。

网络数据只能说明各篇与本库已选文献的连接度，不能等同于领域内的真实地位。种子集由用户筛选，据此算出的枢纽带有循环性，写进提炼时必须把这句话一并交代。

### 第 7 步：收束时生成研究提炼（仅在用户表示暂停或收束时执行）

滚雪球的中间产物是清单与地图，二者都是过程记录，不回答"读完这些文献以后，这个领域在我眼里长成了什么形状、我打算站在哪里"。当用户表示迭代暂停、或明确要求整理成果时，按 `<skill目录>/assets/templates/研究提炼模板.md` 生成 `研究提炼.md`，与检索地图并列放在知识库文件夹内。

**模块次序以精读次序为准**：〇、文献索引；一、文献地位与引用网络；二、已消化文献的功能分层；三、研究问题的演进；四、领域骨架；五、我的位置；六、待解问题与未完成的检索。之所以把网络与功能分层放在最前，是因为用户的实际用法是粗读全部文献之后，靠这份文档决定回去精读谁、按什么线索继续想。若用户说明文档要拿给导师看，可改回传统排法，并在开头注明。

**文献索引是必写项**。全文用"作者＋年份"简称行文，但文首必须给出简称、完整篇名、文件夹内文件名的三列对照表，文件名照录并用反引号包裹。理由：用户读这份文档是为了回去精读，简称无法在文件夹里定位文件，只给篇名也常对不上文件名。正文各节首次出现某篇文献时用"作者《完整篇名》（年份）"，之后回落简称。

生成规则：

1. **只在收束时生成，不每轮都生成**。雪球还在滚时生成会迅速过时。用户若在滚动中途要求更新，照办并注明依据的轮次。
2. **不复述地图**。地图记"推荐了什么、用户选了什么"，提炼记"知识结构长成什么样"。同一批文献在两份文档里的组织逻辑不同：地图按轮次与方向，提炼按地位、脉络与论证角色。
3. **区分已读与待读**。提炼只写已消化文献支撑的判断；待检索的条目只能出现在第六节，不得当作论据使用。
4. **推演须标注**。允许做综合判断（例如指出两条分散的张力合起来构成一个真问题、某两条脉络此前各自成篇而少有交叉），但每处推演都要写明它由哪几项材料推出，让用户能判断这一步是否跳得太远。文献本身说了什么与笔者推演出的结论必须可分辨。
5. **地位分层以网络数据为准**。第一、二节必须依据第 6 步的入度/出度组织，不得沿用轮次顺序。若网络数据显示某篇第一轮文献入度为 0，照实写，并解释这一反差可能来自问题意识不同，而非框架失效。
6. **后文挂回前文**。第三至五节提及某篇文献的重要性时，一律引回第一节的分层结果，不重新论证谁重要。
7. **结构结论按依赖关系归位**。只涉及"谁被谁引用"的事实留在第一节；需要先知道脉络名称才能理解的结论（如"某两条脉络之间只有单向边"）移到第四节相应位置展开。
8. **诚实的缺口**。明确写出哪些方向浅尝辄止、哪些文献没找到、哪些判断证据薄弱。提炼的价值有一半在于说清不知道什么。

## 轮次衔接

每轮输出结束时给出清晰的收尾语，格式大致为：

> 本轮从〔N〕篇文献出发，经〔方向名〕方向筛出〔必读/选读/线索〕共〔M〕条待检索文献，详情已记入 `_检索地图.md`。请手动检索并阅读这些文献，将获取到的 PDF 放入文件夹后再次调用本技能，我将自动读取检索地图进入下一轮。

用户再次调用时，从第 0 步开始。一般滚 3~5 轮后，若用户觉得线索已足够形成选题定位，即停止；是否停止由用户判断，不主动劝停，但可在"下一轮注意"中提示线索边际收益的迹象。

用户表示停止或收束时，除给出收尾语外，依次执行第 6 步与第 7 步：先算引用网络，再据此生成 `研究提炼.md`，并在收尾语中说明该文档的位置与用途。

## 输出行文约束

方向判断与清单面向学术用户，行文遵守以下约定：

- 段落与要点之间有显性衔接词；要点用短句，忌平铺堆叠。
- 少下断语，多用"似乎应当分开来看""值得纳入考察""会不会出自同一个前提"这类留有余地的表达；判断句、关于文献内容的陈述必须挂出处。
- 不用破折号成串列举；不用"不是……而是……"对举句式。
- 语词忌单音节（卖→售、买→购、建→建设、找→寻找），补全省略成分；因果显性化（"之所以……在于……"），指代落实。

## Resources

### scripts/
`scan_library.py`：批量扫描知识库 PDF，输出参考文献区原文、切分后的文献条目、综述/评论候选段落（含页码与信号词）、跨篇共引候选与扫描摘要。详见"运行脚本"一节。

`network_analysis.py`：计算库内互引矩阵、入度/出度分层与库外共引锚点，输出 `network.json` 与 `network_report.md`。第 6 步（收束时）运行；中文文件名不含年份时须先填 `libmap.json`。

### references/
`direction_heuristics.md`：拓展方向的判断指南。定义四把价值尺子（可争辩性、可接续性、可操作性、距离适中），给出六种方向类型各自的识别信号、价值判据与风险，以及把方向改写为检索问题的写法、清单分级约定与三条红线；第六节讲如何把引用网络的结构缺口（断头处、纯来源节点、单向通道、入度为零的新作）当作方向信号。第 3 步之前必读。

### assets/templates/
`检索地图模板.md`：跨轮次状态总账的模板，含文献库清单、轮次记录、已推荐文献总账、研究问题演进记录四部分。第 0 步按它建地图，第 5 步按它更新。

`研究提炼模板.md`：收束时的成果提炼模板，六部分依精读次序排列（文献地位与引用网络／功能分层／研究问题演进／领域骨架／我的位置／待解问题与未完成检索）。第 7 步按它生成 `研究提炼.md`，只在用户暂停或收束时使用。其中"我的位置"一节要动用库内全部研究线索，提出可尝试的方向并标注推出依据。
