# Literature Snowball · 文献检索拓展技能

一个用于**论文写作初期**的 AI Agent 技能：用一组起点文献滚雪球，逐轮拓展可检索的研究线索，并在收束时把成果整理成一份研究提炼文档。

适用于人文社科（社会学、历史学、政治学、传播学、管理学等）的选题定位与文献调研阶段。

## 它解决什么问题

论文初期最常见的困境不是"找不到文献"，而是三件事：

1. **想法模糊**，不知道该往哪个方向找；
2. **顺着参考文献找文献时容易跑偏**，或者凭记忆推荐一些并不相关的"著名文献"；
3. **读完一堆文献之后，说不清这个领域长成了什么形状、自己站在哪里**。

本技能针对这三点分别给出机制：把方向判断交给你选、只推荐库里文献真实引用过的内容、收束时用引用网络重排文献地位并生成提炼文档。

## 工作方式

```
起点文献库（几篇 PDF）
      │
      ├─ 扫描：抽取参考文献、定位综述段落、统计跨篇共引
      │
      ├─ 精读：围绕"共享前提／分歧缺口／受谁影响"三问读综述与评论段
      │
      ├─ 判断：产出 3~4 个拓展方向（含依据、价值、代价）
      │        ↓ 你选定方向
      ├─ 清单：必读／选读／线索 三级文献建议，每条挂出处
      │
      └─ 你手动检索、把新 PDF 放进文件夹 → 进入下一轮
                                    （一般滚 3~5 轮）

收束时：计算库内引用网络 → 生成《研究提炼》
```

## 核心设计

**只推荐库里文献引用过的内容。** 清单中每条文献都必须能在某篇起点文献的参考文献区或正文引用中找到出处。凭模型记忆补出的条目只能进入"线索（需验证）"栏并明确标注。宁可少而准，不可多而虚。

**方向选择权交给用户。** 先给方向判断，等用户选定后才输出该方向的详细清单。不一次性倾倒全部方向，不替用户拍板。

**方向判断必须指回原文。** 每个方向都要能指出是哪篇文献的哪一段支撑它，写不出依据的不列。

**跨轮次状态总账。** 知识库文件夹内维护 `_检索地图.md`，记录每轮方向、清单总账、问题演进，防止重复推荐。

**收束时用数据重排文献地位。** 文献的重要性不按加入轮次或阅读印象判定，而按库内真实的引用关系（入度／出度）计算。第一轮补入的文献未必是枢纽，后补入的可能是全库被引最多的一篇。

## 目录结构

```
literature-snowball/
├── SKILL.md                          技能主文件（工作流程与铁律）
├── scripts/
│   ├── scan_library.py               扫描 PDF：参考文献、综述候选段、共引候选
│   └── network_analysis.py           计算库内引用网络：互引矩阵、入度出度、共引锚点
├── references/
│   └── direction_heuristics.md       方向判断指南（四把尺子、六种方向类型、红线）
└── assets/templates/
    ├── 检索地图模板.md                 跨轮次状态总账模板
    └── 研究提炼模板.md                 收束时的成果提炼模板
```

## 使用

本技能遵循通用的 Agent Skill 约定（YAML frontmatter + Markdown 正文 + 可选脚本与资产）。把整个 `literature-snowball/` 目录放进你的技能目录即可，例如：

- Claude Code / CodeBuddy 类工具：`~/.claude/skills/` 或 `~/.codebuddy/skills/`
- WorkBuddy：`~/.workbuddy/skills/`
- 其他支持 Skill 约定的 Agent：放至其约定的技能目录

随后在对话中给出一个装有 PDF 的文献文件夹路径并说"用这个文件夹做文献滚雪球"即可触发。

### 依赖

- Python 3.8+
- `pypdf`、`pymupdf` 或 `pdfplumber` 三者之一（按此顺序自动探测）
- `network_analysis.py` 的全文补充检索同样依赖上述 PDF 库；若都不可用，脚本会退化为仅使用 `scan_library.py` 已抽取的参考文献文本

安装：

```bash
pip install pypdf
```

### 脚本单独使用

两个脚本都可以脱离技能单独运行，用于任何学术 PDF 文件夹：

```bash
# 扫描：参考文献、综述候选段、跨篇共引候选
python scripts/scan_library.py /path/to/papers

# 计算库内引用网络（须先运行 scan_library.py）
python scripts/network_analysis.py /path/to/papers
```

`network_analysis.py` 需要一份 `_检索扫描/libmap.json` 来指定每篇的作者与年份（中文期刊文件名通常不含年份，自动推断会失败）。脚本首次运行会生成 `libmap.template.json` 供填写。

## 已知限制

- **中文期刊 PDF 的版式差异大。** 双栏版式常使综述段落漏检，字体子集化会导致文本乱码。脚本的抽取只用于辅助定位，判断方向前应回到原文核对语境。
- **参考文献区可能混入同刊他文。** 若某篇 PDF 的参考文献区包含同一期刊另一篇文章的条目，共引统计会失真，需用 `--skip-cocite` 排除该篇。
- **引用网络只反映库内连接度**，不等于领域内的真实地位。种子集由使用者筛选，据此算出的枢纽带有循环性。
- **作者重名会造成误判**，常见姓名需人工抽查若干条边。
- 推荐文献的真实性、可获取性最终由使用者核实。
